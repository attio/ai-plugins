# Explaining the draft

The user sees the explanation before anything is written, so they can understand the model at a glance without inspecting each change. For a single change, one line on why is enough. For a new model or a process, cover:

- The sales motion, citing the user's answer or the strongest signal.
- Why each standard object is in or out, including where Users or Workspaces were used instead of a custom object.
- Why each custom object isn't really a company, person, user or workspace.
- Why each list is included, and which object it sits on.
- Why each set of stages fits how the team works.
- The relationships that aren't obvious, showing you checked whether each value should be a link.
- What you're reusing from the workspace.
- What the user confirmed, and each assumption still in place because the user had no preference, so they can correct it.
