# Lists

A list is a staged process the team runs on some existing records: onboarding customers, raising a round, hiring, managing a portfolio. When the thing being tracked is a process run on companies or people, use a list, not a custom object. Put the list on the record the team works: a Customer Success list normally sits on Companies, but on Workspaces if the user syncs product data there.

A good list has a stage, an owner, an amount where money is involved, and a reason for losing or passing. Give it one pipeline view plus 2 or 3 filtered table views.

You can create a list and its views, but not attributes on the list itself. So put the list's stage and attributes on the record it sits on, and name the stage after the process, such as Customer stage, so it doesn't clash with other stages. Set the stages in the draft, in order and ending with the outcomes, since you can't change them after. The pipeline view is a kanban grouped by that stage.

If you're not sure a list applies, ask, and recommend leaving it out. Lists are easy to add later.
